# Процедура разработки FHD / SRHD

## Хранение и версионирование

- Репозиторий модов: исходный код, CFG, исходные ресурсы по возможности, файлы сборки, документация и тесты. Не использовать GitHub как основное место для многогигабайтных готовых архивов.
- Google Drive: готовые архивы и крупные игровые ресурсы; каталог обновлений должен получать версии из Drive без ручного изменения ссылок.
- Не удалять и не заменять существующие исторические папки, архивы и версии при первичной инвентаризации.
- Записывать происхождение каждого импорта: точное имя исходного архива, версию и тип проверки. Папка `incoming/` означает «исходники обнаружены, но релиз не подтверждён».

## Совместимость и сборки

- Любые зависимости от Rangers.exe (DLL, хуки, адреса, вызовы, патчи) одновременно проверять под старый и новый EXE. Выбор варианта — автоматически по хешу EXE, без ручного переключателя.
- Каждый мод должен иметь TEST ↔ RELEASE. При наличии подходящего конфигурационного блока переключение осуществляется одной правкой и пересборкой Main.dat/Lang.dat при необходимости.
- Не считать `Build=RELEASE` стандартом — это не проверенный механизм.
- Для FHD_SET v2.4.6 подтверждён пример: `CFG/Rus/Lang.dat` → `Script.FHDSETv1.BuildMode { 001=int result=0; }`: 0=RELEASE, 1=TEST. **Не копировать это название блока в другие моды без адаптации**.
- Не добавлять запускаторы .cmd и не модифицировать установленную папку игры ради разработки.

## Контроль качества

1. Исходная рабочая версия фиксируется отдельно от кандидатов.
2. Точечные правки и сравнение diff; избегать побочного изменения механик.
3. Статические тесты + сборка; для DLL проверка обеих версий EXE.
4. Ручное тестирование в игре с логами и фиксацией версии; только после этого помечать RELЕASE.
5. Хранить тексты, конфиги и исходные графические файлы в диффируемом виде, когда это возможно.

## Безопасность публикации

- Перед публикацией проверять `secret`, `token`, `password`, `.env`, ключи Cloudflare/Render/Supabase/GAS и приватные URL.
- Реальные секреты хранить в настройках соответствующего сервиса, а в репозитории — лишь имена переменных/примеры без значений.
- Репозитории аккаунта на момент инвентаризации были публичными; не переносить непроверенное содержимое серверных конфигов автоматически.
